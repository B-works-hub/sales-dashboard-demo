# 일일 매출 대시보드 — 데모

구글 시트에 쌓이는 일일 매출을 팀이 매일 열어 보는 한 장짜리 대시보드로 만든
것입니다. 실제로 운영 중인 도구의 **데모판**이고, **화면의 숫자·판매처·상품은
전부 생성된 가상 데이터**입니다.

**[▶ 열어 보기](https://hyejeonginsight-pixel.github.io/sales-dashboard-demo/)**

```text
  판매 현황    KPI 카드 4장 · 판매처별 누적 막대 그래프 · 판매처 × 날짜 표
               상품 × 날짜 표 · 칸에 붙는 메모 · 기간/판매처/제품군 필터
  프로모션 리뷰 기획전 하나를 골라 카드 일곱 장 — 발신 성과 · 구매 고객 구성
               직전 7일/30일/작년 대비 증감 · 유입 · 객단가 · 구매 조합
  공통         URL 로 화면 저장 · CSV 내려받기 · 다크 모드 · 모바일
```

프로모션 리뷰는 상단 **`프로모션 리뷰`** 탭에서 볼 수 있습니다
(promotion 을 고르면 탭이 나타납니다).

---

## 무엇을 풀었나

숫자를 보여주는 것보다, **틀렸을 때 조용히 넘어가지 않게** 만드는 데 시간을 더
썼습니다. 아래는 실제로 겪고 고친 것들입니다.

### 1. 페이지에 매출을 두지 않기

저장소가 공개인데 대시보드는 사내용이어야 했습니다.

```text
  ┌──────────────┐  ①로그인   ┌────────┐
  │ 정적 페이지    │ ─────────▶ │ 구글    │
  │  (빈 껍데기)  │ ◀───────── │ 인증    │
  └──────┬───────┘  ②토큰     └────────┘
         │ ③받은 토큰으로 직접 요청
         ▼
  ┌──────────────┐
  │  구글 시트     │  ← 숫자는 전부 여기
  └──────────────┘
```

페이지에는 계산식만 있고 숫자가 없습니다. 보는 사람이 **자기 계정으로** 시트에서
가져오고, 권한 판단은 페이지가 아니라 **구글이** 합니다. 그래서 소스를 열어도
매출이 보이지 않고, 사내 도메인 계정이 아니면 화면이 비어 있습니다.

> 이 데모판은 그 자리에 가상 데이터를 끼워 넣어 로그인 없이 열립니다.
> `sheetValuesOf()` 한 함수만 바꿨고, 집계·표·그래프 코드는 그대로입니다.

### 2. 열을 위치가 아니라 이름으로 찾기

시트 중간에 열이 하나 끼어들어 **모든 숫자가 한 칸씩 밀린 적**이 있습니다.
그 뒤로 첫 행의 이름으로 찾습니다.

```js
var COL_ALIASES = {
  date: ['날짜', '주문일', '주문일자'],
  ch:   ['채널명', '판매처', '채널'],
  amt:  ['매출', '주문금액', '금액', '매출액'],
  …
};
```

이름을 못 찾으면 **화면에 그 사실을 적습니다.** 각주의 `열 인식: 날짜=A열 …` 줄이
그것이고, 숫자가 이상할 때 여기부터 보게 됩니다.

### 3. 설정을 코드가 아니라 시트에 두기

판매처 목록·표시 순서·표기 보정·제품군을 시트의 `설정` 탭에서 읽습니다.
판매처가 하나 늘어도 **시트에 한 줄 적으면 끝**이고, 배포가 필요 없습니다.

부수 효과가 하나 더 있었습니다 — 거래처 명단이 공개 소스에서 사라집니다.
로그인한 사람에게만 내려갑니다.

### 4. 조용히 틀리지 않기

이 도구에서 가장 신경 쓴 부분입니다.

| 상황 | 어떻게 |
| --- | --- |
| 설정 탭을 못 읽음 | 기본값으로 돌되 **각주에 그 사실을 적음** |
| 메모 탭이 없음 | 화면은 그대로, 메모만 안 붙음 |
| 열 이름이 바뀜 | 어떤 열을 못 찾았는지 이름을 짚어 안내 |
| 시트 권한 없음 | "권한을 요청하세요" — 원인별로 다른 문구 |

빈 화면에 "오류가 발생했습니다"만 뜨면 아무도 고칠 수 없습니다.
**무엇을 어떻게 하면 되는지**까지 적습니다.

### 5. 탭 이름 대신 gid 로 찾기

시트 탭 이름은 사람이 언제든 바꿉니다. 이름으로 찾으면 그때마다 깨져서,
탭 고유번호(`gid`)로 찾고 이름은 그때그때 조회합니다. 탭 목록은 파일당 한 번만
받아 두므로 요청이 늘지 않습니다.

### 6. 색을 눈으로 고르지 않기

판매처 15곳에 색을 주는데, 인접한 두 곳이 **색약 상태에서 구분되는지** 확인하며
명도 계단으로 배치했습니다. 연두와 노랑은 한 번 겹쳤다가 다시 벌린 조합입니다.

표의 파란 농담은 **열마다 따로** 계산합니다. 판매처끼리 크기를 견주는 색이 아니라,
각 판매처가 자기 기준으로 잘 판 날을 찾는 색입니다.

### 7. 일평균을 기존 방식과 맞추기

```text
  일평균 = 실적이 있는 날의 합 ÷ 실적이 있는 날 수
```

빈칸은 분모에서 빼고 0은 넣습니다. 팀이 쓰던 스프레드시트 피벗과 숫자가 맞아야
"이 도구가 틀렸다"는 말이 안 나옵니다. **새 도구는 기존 숫자와 맞는 것부터**입니다.

## 만듦새

- **의존성 없음** — HTML 한 장. 빌드도, 프레임워크도, 패키지도 없습니다
- **ES5 문법** — 사내 구형 브라우저를 고려했습니다
- **다크 모드 · 모바일** — `prefers-color-scheme` 과 반응형 표
- **URL 에 화면 상태 저장** — `?ch=…&month=…&metric=qty` 로 같은 화면을 공유
- **키보드 · 스크린리더** — 메모 칸은 `tabindex` 와 `Enter`/`Esc` 로 열고 닫힘

## 이 저장소

```text
  index.html          대시보드 (데모판)
  demo-data.js        가상 데이터 — tools/make-data.py 로 만듦
  tools/make-data.py  데이터 생성기
```

데이터를 다시 만들려면:

```bash
python tools/make-data.py > demo-data.js
```

요일 주기·완만한 성장·채널 편중·기획전 구간을 넣어 그럴듯한 모양을 만듭니다.
난수만 뿌리면 그래프가 톱니처럼 보이고 증감률이 의미 없는 값이 됩니다.

## 프로모션 리뷰 — 숫자가 어디서 왔는지 밝히기

기획전 하나를 고르면 카드 일곱 장이 펼쳐집니다. 이 화면에서 가장 신경 쓴 건
표가 아니라 **숫자의 출처를 감추지 않는 것**입니다.

같은 매출도 어느 장부에서 뽑느냐에 따라 다릅니다.

| | 무엇 | 취소·환불 |
| --- | --- | --- |
| **마감 기준** | 월마감 후의 주문 원장 요약 | 반영됨 |
| **잠정 기준** | 매일 쌓는 일일매출 원본 | 아직 안 빠짐 |

카드 위 띠에 **어느 쪽으로 계산했는지** 배지로 답니다. 그리고 **한 리뷰 안에서
두 장부를 섞지 않습니다** — 비교 구간(직전 7일·30일·작년) 중 하나라도 원장 밖이면
네 구간 모두 잠정치로 냅니다. 섞으면 증감률이 한쪽으로 기울기 때문입니다.

데모에서 두 기획전을 나란히 보면 한쪽은 `마감`, 다른 쪽은 `잠정` 배지가 붙습니다.
작년 동기간이 원장 범위 밖이라 자동으로 물러선 것이고, 그 사실도 화면에 적힙니다.

### 분모를 아무거나 쓰지 않기

전환율과 객단가는 **분자에 없는 사람을 분모에 넣지 않도록** 갈라 두었습니다.

```text
  객단가(총매출)            ÷ 행사기간에 산 모든 고객
  객단가(행사품목만)         ÷ 행사품목을 산 고객
```

고객 수는 주문 원장에서 **연락처의 고유 개수**로 셉니다 — 한 사람이 기간 안에 두 번
사거나 아이디를 여러 개 써도 한 명입니다. 연락처 열이 없으면 주문자 ID 로 물러서고,
**그렇게 셌다는 사실을 각주에 적습니다.**

### 구매 조합

행사품목을 산 사람이 **무엇을 함께 담았는지** 많이 나온 순으로 봅니다.
한 사람이 여러 번 샀으면 한 조합으로 묶고, **수량까지 같아야 같은 조합**입니다.
정기배송과 사은품은 고른 것이 아니라서 조합에서 뺍니다.

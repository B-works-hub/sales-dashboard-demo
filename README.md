# 매출 리포트 — 데모

구글 시트에 쌓이는 매출을 팀이 열어 보는 화면으로 만든 것입니다.
실제로 운영 중인 도구들의 **데모판**이고, **화면의 숫자·판매처·상품은 전부
생성된 가상 데이터**입니다.

**[▶ 열어 보기](https://b-works-hub.github.io/sales-reports-demo/)**

```text
  매일    일일 매출        판매처별 일일 주문금액 · 상품 × 날짜 표 · 메모 · 프로모션 리뷰
  달마다  고객             신규·재구매·이탈 · 재구매 주기와 횟수 · 연령대 · 정기배송 코호트
          상품별           제품라인 14종의 경험률 · 첫구매 · 재구매 · 리필 구매 연결
          판매처별         채널 계층별 월 실적 · sell-out / sell-in 이중 장부
          Chart            카테고리 × 제품라인 × 채널 · 수량/금액 · MTD / YTD
          플래그십         매장 방문객 요일·시간대별 · 내/외국인 국적별 · 상품 TOP 10
```

일일 매출은 완성돼 있고, 월간 5종은 만드는 중입니다.

---

## 두 개의 원장

리포트를 따로 만들면 **판매처별의 「자사몰 7월」과 Chart 의 「자사몰 7월」이
어긋납니다.** 한 화면에서 대조되는 순간 데모가 자기모순이 됩니다.

그래서 월간 5종은 가상 주문 원장을 **한 번만** 만들고 전부 거기서 집계합니다.

```text
  tools/master.py    채널 19 · 제품라인 14 · SKU 28 · 기간 2024.01~2026.07
        ↓
  tools/ledger.py    가상 주문 원장  ← 월간 5종의 유일한 진실
        ↓
  tools/build_*.py   리포트별 집계 → data/*.js
```

원장 자체는 커밋하지 않습니다. 13만 줄짜리를 다섯 번 실으면 저장소가
수십 MB 가 되고, 리포트가 실제로 쓰는 건 집계 결과뿐입니다.

**일일 매출은 이 원장을 쓰지 않습니다.** 먼저 만들어진 별도 데모이고, 다시
생성하면 이미 검증된 화면을 흔들게 됩니다. 판매처 이름만 같게 맞춰 두고,
**합계가 일치하지 않는다는 사실은 화면 각주에 적습니다** — 조용히 어긋나
있는 것보다 낫습니다.

## 숫자를 아무렇게나 만들지 않기

난수만 뿌리면 그래프가 톱니처럼 보이고 증감률이 의미 없는 값이 됩니다.
원장 생성기에는 이런 것들이 들어 있습니다.

| | 무엇 |
| --- | --- |
| 계절성 | 12월 선물 시즌, 여름 비수기 · 요일 주기 |
| 기획전 | 기간·배수를 가진 구간 5개 |
| 성장 | 완만한 우상향 + 수출 개시(2025.11)로 한 단 |
| 장바구니 | 선물 시즌에 함께 커집니다 — 빼면 객단가가 ±4% 안에서만 움직여 증감률이 전부 0% 근처로 뭉개집니다 |
| 채널 성격 | 대량주문은 **건수가 적고 건당이 큽니다.** 주문 빈도를 매출 비중으로 쓰면 대량주문이 매출의 절반을 먹습니다 — 빈도는 `매출비중 ÷ 건당수량` 으로 역산합니다 |

생성기는 목표 연매출에 맞춰 **주문 수**를 반복 보정합니다. 금액을 사후에
곱해 맞추면 `정가 × 수량` 이 깨져 표의 검산이 안 됩니다.

난수는 날짜마다 독립 시드입니다. 전역 시퀀스 하나를 쓰면 주문 수를 조금만
바꿔도 뒤의 모든 날이 뒤틀려 보정이 ±5% 로 진동합니다.

## 만듦새

- **의존성 없음** — 빌드도, 프레임워크도, 패키지도 없습니다
- **토큰 공유** — `shared/tokens.css` 하나로 색·다크모드·색각 계단을 맞춥니다
- **다크 모드 · 모바일** — `prefers-color-scheme` 과 반응형 표
- **URL 에 화면 상태 저장** · **CSV 내려받기** · **키보드 · 스크린리더**

## 이 저장소

```text
  index.html          허브
  daily/              일일 매출 — 자체 데이터·자체 스타일 (아래 README 참고)
  customer/  product/  channel/  chart/  flagship/
  shared/             tokens.css · report.css · report.js
  data/               리포트별 집계 결과
  tools/              master.py · ledger.py · build_*.py
```

- 일일 매출의 설계 이야기 — [`daily/README.md`](daily/README.md)

월간 리포트 데이터를 다시 만들려면:

```bash
cd tools && python3 build_all.py
```

## 알림

실제 운영본의 리포트 구조를 옮겨 만든 데모입니다.
**실제 매출·거래처·상품 정보는 한 줄도 들어 있지 않습니다.**
판매처명·제품명·제품라인 코드는 전부 새로 지은 것이고, 모든 수치는
`tools/` 의 생성기가 만든 가상 데이터입니다.
